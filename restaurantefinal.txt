RESTAURANTE PRO
ESPECIFICACIÓN COMPLETA Y DEFINITIVA DEL SISTEMA
Arquitectura: 3 aplicaciones conectadas a un mismo backend, autenticación, seguridad y base de datos.
Aplicaciones: (1) App Cliente móvil, (2) App Administrador móvil y (3) Restaurante Desktop.
1. Objetivo general
Crear una plataforma profesional para restaurantes donde los clientes puedan encontrar un restaurante, escanear un QR o
buscarlo por nombre/código, consultar el menú, hacer pedidos y pagar; mientras que el restaurante pueda administrar su
operación desde una computadora o un teléfono.
Regla principal: la experiencia del cliente y la administración deben estar separadas. No se debe mezclar el dashboard
administrativo dentro de la App Cliente.

Las tres aplicaciones usan la misma información central. No se crean bases de datos separadas para cada aplicación.
3. Las tres aplicaciones
1. App Cliente: exclusivamente para clientes que quieren consultar restaurantes y realizar pedidos.
2. App Admin: para propietario y empleados autorizados desde teléfono o tablet.
3. Restaurante Desktop: para administrar el restaurante desde computadora y trabajar con caja, cocina, meseros, inventario y
reportes.

38. Resultado final
El resultado será una plataforma profesional de restaurante con tres aplicaciones claramente separadas. El propietario registra
el restaurante una sola vez, configura el negocio y crea los usuarios de sus empleados.
Cada empleado entra con usuario o correo y contraseña. El servidor identifica automáticamente su rol y lo envía al panel
correspondiente: Mesero, Caja, Cocina, Gerente o Administrador.
El cliente utiliza otra aplicación completamente independiente para buscar restaurantes, escanear QR, consultar menús,
realizar pedidos, seguir su pedido y pagar.
Todo se mantiene conectado mediante el mismo backend, autenticación, seguridad y base de datos.
Nota de pagos: tarjeta, NFC/contactless, reembolsos y otras funciones financieras deben implementarse con proveedores
compatibles con el país, banco/adquirente, dispositivo y requisitos regulatorios. La aplicación no debe almacenar directamente
datos sensibles de tarjetas.
